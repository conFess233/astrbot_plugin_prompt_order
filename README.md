<h1 align="center">AstrBot 提示词编排</h1>

<p align="center">自动识别每个插件注入的提示词片段，按你拖拽排好的顺序发出，让前缀缓存更稳定；压缩历史里反复重发的长工具结果；附带可以实时监控的调用检查器。</p>

DeepSeek、OpenAI、Anthropic 等模型只缓存“从开头开始完全相同”的那一段提示词。插件一多，每轮都在变的内容（记忆等）和固定不变的内容（规则、说明）混在一起，固定内容就可能每轮都得重新计费。本插件找出每段内容是哪个插件加的、多久变一次，把固定的排在前面、会变的排在后面。

## 核心亮点

| 能力       | 说明                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------- |
| 来源追踪   | 给其他插件的 `on_llm_request` 钩子各套一层，前后各拍一次快照，每处改动都记到具体插件名下；新装的插件不用写规则 |
| 拖拽排序   | SYSTEM 区（会被缓存）、TAIL 区（每轮附加内容）、TOOLS 区三栏拖拽，可以跨区移动                                 |
| 缓存警告   | 按最近请求统计每个片段的稳定度和出现率，排法会破坏缓存时直接标出来，并提供“推荐排序”                           |
| 安全保护   | 会写入历史的片段不能移进 SYSTEM；重排前后内容不一致、或出现任何异常时，请求原样发出                            |
| 历史压缩   | 已结束回合的长工具结果（联网搜索、知识库等）由小模型提炼成笔记替换进历史，历史提醒块压成一行；每段只压一次，不额外打破缓存 |
| 调用检查器 | 查看实际发出的 HTTP 请求、每个插件注入了什么、模型、轮数、用量与命中率；支持实时推送、按天落盘和保留策略       |

<a id="quick-start"></a>

## 快速开始

运行要求：AstrBot 4.29.0 及以上（需要插件可视化视图）。没有额外的 Python 依赖。

1. 把 `astrbot_plugin_prompt_order` 目录放到 AstrBot 的 `data/plugins/` 下，在 WebUI 插件页重载插件。
2. 插件默认处于**试运行**：只追踪、只统计，不改写任何请求。建议让 bot 正常回复一些消息，积累统计数据后再关掉试运行进行排序。
3. 打开插件管理页“提示词编排”，在“排序”页点“推荐排序”，检查右侧的预览和警告，确认后保存。
4. 确认无误后，关闭页面右上角的“试运行”开关，重排结果才会写回请求。

<a id="usage"></a>

## 使用方法

本插件没有聊天指令，所有操作都在插件管理页“提示词编排”中完成。

### 排序

- **布局**：一组会话共用的片段顺序。“会话范围”填 umo 通配符（例如 `xxx:GroupMessage:*`），按列表顺序匹配第一个命中的布局；范围留空的布局作为兜底。
- **未排片段**：最近请求中出现、但布局里还没写到的片段，按来源插件分组。可以拖进下方的区，也可以用卡片上的按钮移动；“整组放入原区”会写入 `插件名/*`，之后这个插件新出现的片段也会排在这里。
- **SYSTEM 区**：放常驻且内容不变的片段，越靠前越好。
- **TAIL 区**：本轮附加内容，用户原话固定在最前。
- **TOOLS 区**：可以选择保持原样、按名字排序或自定义顺序。工具位于整个提示词最前面，增删工具会让后面的缓存全部失效。
- **占位项**：“未排片段”是布局里没写到的片段的落点，它们留在原区，保持原来的相对顺序；“图片 / 音频”只能留在 TAIL 区。
- **细分与别名**：点开片段卡片，可以给同一个插件的多块内容加锚点、切成几段；某个片段第一行变化、被识别成新片段时，可以用别名指向原来的片段。
- **保存**：修改先作为草稿，右下角按钮会变成“放弃 / N 个布局未保存 / 保存”。每次保存生成一个新版本，“历史版本”里可以回滚。

**片段缺失时**：某个插件被关闭、本轮没有它的片段时，跳过即可，其余片段仍保持布局里的相对顺序。布局里该片段的位置会保留，插件重新打开后自动回到原位。

**跨区通配符**：`插件名/*` 只匹配原本就在该区的片段。要把某个片段跨区移动（比如把每轮都一样的规则从 TAIL 移进 SYSTEM），需要单独放置这个具体片段。

### 检查器

顶部汇总可在“今日 / 本周 / 本月 / 自定义”之间切换日期范围，并按“合计 / 主模型 / 旁路调用”查看调用次数、输入与命中率、输出和平均轮数；范围跨多天时显示每日输入 tokens 趋势（命中 / 未命中），下方附按模型、按会话的拆分。

调用列表按同一日期范围列出每次调用：会话、模型、轮数、输入 tokens 与命中率、耗时。筛选条件改动后自动查询。点击一行查看详情：

| 子标签   | 内容                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------ |
| 实际请求 | 线路层记录的请求体，逐条消息折叠显示；取不到时显示调用层入参并加以标注                                 |
| 注入来源 | SYSTEM 来源表（按插件上色）、每个钩子的改动、重排前后对比                                              |
| 响应     | 回复正文、思考内容、工具调用、结束原因                                                                 |
| 用量     | 统一用量与供应商原始 usage；“找出前缀从哪里开始不同”会对比同会话上一次调用，直接说明这一轮为什么没命中 |
| HTTP     | 每一次尝试（包括 SDK 自动重试）的地址、状态码、耗时、脱敏后的请求头                                    |

详情里点“设为对比基准”，再打开另一条记录点“与基准对比”，可以看到两次调用的 SYSTEM 从哪一行开始不同、工具列表是否变化，以及逐行差异。

“检查器开关”里可以修改捕获深度、旁路调用、过滤、落盘与保留策略，也可以清空记录。

### 清除历史思考（仅 DeepSeek）

排序页右上角的“清除历史思考”开关。开启后，发给 DeepSeek 的请求在发送前，会把已结束轮次里模型的思考内容（`reasoning_content`）清空：

- 本轮工具调用链的思考保留，DeepSeek 要求在工具循环中原样回传。
- 字段保留为空字符串，DeepSeek V4 要求历史 assistant 消息带这个字段。
- 只改发出的请求，AstrBot 保存的对话历史不受影响；关闭开关即恢复原样。
- 模型名或接口地址里带 `deepseek` 才生效，其他模型不处理。

开启后的第一次请求，历史部分会有一次缓存未命中；之后前缀重新稳定。检查器“实际请求”里会显示每次清空了多少条。

### 省略历史图片

排序页右上角的“省略历史图片”开关。开启后，发送前把已结束轮次里的图片换成固定的文字占位 `[图片：历史图片已省略]`：

- 本轮用户发的图片、本轮工具返回的图片保留。
- 只改发出的请求，AstrBot 保存的对话历史不受影响；关闭开关即恢复原样。
- 支持 OpenAI 兼容接口与 Gemini 接口，不区分模型。

每张历史图片每次请求都要按图片计费，Gemini 还要每次从磁盘重新读取，文件丢失时整条请求会失败。开启后模型看不到旧图，用户追问旧图时需要靠识图插件的回看或自动召回功能。检查器“实际请求”里会显示每次替换了几张。

### 压缩 JSON

排序页右上角的“压缩 JSON”开关（默认开启）。发送前把本轮不存档片段里的 JSON（例如 ContextAware 的图片目录）去掉多余空白：

- 字段、值、顺序都不变，中文保持原样（不转成 `\uXXXX`）。
- 只处理从行首开始、能完整解析、至少 80 字的 JSON 块；其余文字不动。
- 只处理本轮不存档的片段，不影响对话历史。
- 不受“试运行”影响；关闭“启用重排”时不生效。

线上的图片目录本来就是单行 JSON，只能去掉 `, ` 和 `: ` 后面的空格，大约少 5%（每轮约 50 字）。目录里的空字段和末尾的固定说明，需要用下面的改写规则自行处理。

### 常驻说明与改写规则

这两项完全由你决定内容，插件不会自动判断哪些文字可以移动或删除。

- **常驻说明**：SYSTEM 区标题旁的“常驻说明”按钮，写一段每轮都一样的文字，作为一个片段放进 SYSTEM 区（会被缓存），可以拖动调整位置。点开卡片可以修改或删除。
- **改写规则**：点开 TAIL 区的某个片段，在详情里添加“查找 → 替换为”规则，替换为空即删除。可以选择只作用于这个片段，或作用于同一来源的全部 TAIL 片段；支持 Python 正则表达式。规则按顺序执行，之后再做 JSON 压缩。勾选“同时把查找的文字加为常驻说明”，可以一步把一段固定说明从本轮片段移进 SYSTEM 区，之后再改写措辞。

右侧“用草稿预览”会对所选样本演示效果：每条规则在该样本里命中几处、少了多少字，以及片段改写后的全文。规则在重排生效（非试运行）时才作用于请求；改动会记在“改动记录”里。

把说明从片段旁边移进 SYSTEM 区，可能让它的约束变弱；条件性的说明（只在某个片段出现时才有意义）最好改写成“若出现……则……”。会影响插件功能的固定要求（例如好感度插件要求回复最后一行输出标签）不建议移动。

### 历史压缩

联网搜索、知识库等工具的结果动辄几千字，回合结束后仍留在对话历史里，之后每次请求都要重发，直到被截断。线上一周的数据里，历史中的工具结果约占主对话输入的两成，一条 6000 字的搜索结果平均被重发 30 次；历史消息里的 `<system_reminder>` 又占一成多。

开启后：

- **提炼**：回合结束、回复已经发出后，用配置的提炼模型把本轮的长工具结果提炼成笔记。提炼时带上用户的问题和机器人的最终回答，只保留相关的事实和最多 3 个来源；同一回合的多条结果合成一条摘要，放在第一条结果里，其余标注“已并入”，工具调用配对不变。
- **替换**：下一轮请求前，把历史里的原文换成摘要。上一轮的提炼还没完成时，最多等“等待提炼”设置的秒数。
- **规则截取**：没有提炼模型、提炼失败或等待超时时，按规则截取：搜索结果保留标题、链接和摘要开头；知识库结果去掉 YAML 文档头、合并重复片段；其他工具保留开头。截取后的内容不会再被替换成摘要。
- **提醒块**：历史消息里的 `<system_reminder>User ID: …, Nickname: …
Current datetime: …</system_reminder>` 压成 `[昵称(ID) 2026-11-11 14:55]`。本轮消息保持完整。

压缩后的内容会随本轮一起写回 AstrBot 保存的对话历史，所以每段内容只压缩一次，之后每次请求发的都是同样的文本。被压缩的内容都在上一轮用户消息之后，这一段本来每轮都要重新计费，所以不会额外降低缓存命中。**这是有损的**：原文不会保留在对话历史里，模型需要细节时要重新调用工具（摘要开头会提示这一点）；原文和摘要的对照保存在插件数据里 30 天。

默认处于试运行：照常提炼并记录“每次请求可少发多少字”，但不改写历史。在管理页“历史压缩”里对照原文检查提炼质量，确认后关闭试运行。关闭后的第一次请求会把已有历史一次压缩完，有一次缓存未命中。

本轮的工具结果保持原样，模型当次回答看到的是完整原文；从下一轮起才换成摘要或节选。

### 改动记录与覆盖范围

“改动记录”按执行顺序列出每个钩子对请求做了什么，在重排之后才发生的改动会标红。“覆盖范围”列出哪些改动能识别、能排序，以及本次运行实际检测到的情况。

## 配置

宿主配置页放总开关、历史压缩与检查器设置；布局（包括常驻说明和改写规则）在管理页编辑。修改后立即生效，不需要重载插件。

| 配置键                                      | 默认值      | 作用                                                                             |
| ------------------------------------------- | ----------- | -------------------------------------------------------------------------------- |
| `enabled`                                   | `true`      | 启用重排。关闭后只追踪和统计                                                     |
| `dry_run`                                   | `true`      | 试运行：只计算重排结果，不写回请求                                               |
| `stats_window`                              | `200`       | 每个布局按最近多少次请求统计稳定度，20～2000                                     |
| `sample_limit`                              | `30`        | 保留多少次请求的完整片段用于预览，5～200                                         |
| `diff_char_limit`                           | `50000`     | 某个插件整体改写 system 且超过这个长度时，整段记到该插件名下，不再逐字对比       |
| `strip_reasoning`                           | `false`     | 清除历史思考（仅 DeepSeek）：发送前清空已结束轮次的思考内容                      |
| `strip_history_images`                      | `false`     | 省略历史图片：发送前把已结束轮次的图片换成文字占位                               |
| `minify_json`                               | `true`      | 压缩本轮不存档片段里的 JSON，内容不变                                            |
| `compact.enabled`                           | `true`      | 启用历史压缩                                                                     |
| `compact.dry_run`                           | `true`      | 试运行：照常提炼并统计，不改写历史                                               |
| `compact.reminders`                         | `true`      | 把历史消息里的提醒块压成 `[昵称(ID) 时间]`                                       |
| `compact.tool_results`                      | `true`      | 压缩已结束回合的长工具结果                                                       |
| `compact.distill_provider_id`               | 空          | 提炼模型，建议便宜快速的模型；留空只按规则截取                                   |
| `compact.digest_max_chars`                  | `500`       | 摘要长度上限，150～3000                                                          |
| `compact.wait_seconds`                      | `4`         | 下一轮来得太快时最多等提炼几秒，超时按规则截取，0～20                            |
| `compact.min_chars` / `block_min_chars`     | `600` / `1200` | 单条结果、单个回合合计低于此长度不处理                                        |
| `compact.snippet_chars`                     | `150`       | 规则截取时每条搜索结果保留的字数，知识库片段保留两倍                             |
| `compact.exclude_tools`                     | 空          | 每行一个不压缩的工具名，支持通配符                                               |
| `inspector.enabled`                         | `true`      | 启用检查器                                                                       |
| `inspector.depth`                           | `wire`      | `wire` 记录实际发出的请求；`call` 只记模型、用量和轮数                           |
| `inspector.capture_side`                    | `false`     | 记录插件自己调用模型的旁路请求                                                   |
| `inspector.umo_include` / `umo_exclude`     | 空          | 每行一个 umo 通配符                                                              |
| `inspector.save_response`                   | `true`      | 保存回复正文                                                                     |
| `inspector.fold_media`                      | `true`      | 把 base64 图片、音频替换为带大小和摘要的占位文字                                 |
| `inspector.body_limit_kb`                   | `2048`      | 单次请求体上限，超出截断，64～16384                                              |
| `inspector.persist`                         | `true`      | 落盘保存                                                                         |
| `inspector.retention_days` / `retention_mb` | `7` / `500` | 超过任一上限，从最旧的一天开始删除                                               |
| `inspector.memory_traces`                   | `200`       | 内存中保留的记录数                                                               |
| `inspector.prices`                          | 空          | 每行 `模型名=未命中输入,命中输入,输出`（美元 / 百万 tokens），填写后显示估算费用 |

## WebUI

在 AstrBot WebUI 的插件管理中打开“提示词编排”页面，需要 Dashboard 登录。共有五个模块：排序、检查器、历史压缩、改动记录、覆盖范围。页面跟随宿主的明暗主题，支持窄屏和键盘操作（片段卡片可以用 Alt+↑/↓ 移动）。

## 数据与安全

```text
data/plugin_data/astrbot_plugin_prompt_order/
├── config.json          # 当前布局与版本号
├── versions/            # 最近 50 个历史版本
├── stats.sqlite         # 每个布局最近 N 次请求的片段哈希
├── samples.json         # 最近若干次请求的完整片段（用于预览）
├── compact.sqlite       # 工具结果原文与摘要、每次压缩的节省量（保留 30 天）
└── inspector/
    ├── traces/YYYY-MM-DD.jsonl   # 调用记录，按天分文件
    ├── index.sqlite              # 记录索引
    └── inflight.json             # 进行中的记录，重启后补写为“中断”
```

- 样本和调用记录包含完整的提示词与消息内容（可能包含群聊发言），请按需设置保留天数，或关闭落盘。
- `Authorization`、`x-api-key` 等请求头一律替换为 `***`，不受任何开关影响，所以落盘文件里不会有 API 密钥。
- 本插件自己不发起外部网络请求。配置了提炼模型时，会通过 AstrBot 调用该模型，把工具结果原文、用户问题和机器人回答发给它。

<a id="limits"></a>

## 已知限制

- 历史消息和用户原话不参与排序。附加片段无法排到用户原话前面，这是宿主拼装请求的方式决定的。
- 插件在钩子之外修改请求（后台任务修改请求对象、直接修改 provider）时，本插件看不到。比本插件重排（优先级 -99999）更晚执行的钩子所做的改动，能检测到并标红，但不参与排序。
- 旁路调用只能由检查器记录，不参与排序。
- 历史压缩只处理已结束回合；本轮工具循环里的结果无法在当次压缩。
- 线路层依赖 provider 底层的 httpx 客户端（OpenAI 兼容、Anthropic 等）。没有 httpx 客户端时，退回记录 SDK 入参或只记录调用层，页面会标注。
- 第一次保存会改变 SYSTEM 或工具顺序的布局后，命中该布局的会话缓存会失效一次。
- 本插件在与[astrbot_plugin_prompt_inspector](https://github.com/nikonotnicotine/astrbot_plugin_prompt_inspector)一同运行时，会出现反复往 provider 上套包装，层数越叠越多导致重复记录请求的问题，目前本插件已进行修复，只记录最外层的包装。
